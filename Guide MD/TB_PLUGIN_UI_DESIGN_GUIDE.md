## 1. 목적

이 문서는 TB 오디오 플러그인 전반에 일관된 시각 언어와 UX를 적용하기 위한 기준이다.
하나의 화면을 그대로 복제하는 것이 아니라, 같은 제품군으로 인식되면서 각 플러그인의
핵심 음악적 목적이 즉시 드러나는 것을 목표로 한다.

모든 디자인은 다음 두 조건을 만족해야 한다.

- 사용자가 한눈에 TB 플러그인 제품군임을 인식할 수 있어야 한다.
- 설명서를 읽지 않아도 핵심 조작 흐름과 우선순위를 이해할 수 있어야 한다.

## 2. 디자인 시작 전 필수 규칙

### 2.1 컨셉 컬러를 팔레트 형식으로 먼저 확정한다

컴포넌트를 그리면서 임의로 색상을 추가하지 않는다. 레이아웃과 스타일 구현을 시작하기 전에
아래 형식의 시맨틱 팔레트를 작성하고 확정한다.

| 토큰 | HEX | 역할 | 사용 범위 |
| --- | --- | --- | --- |
| `canvas-top` | `#000000` | 메인 섀시의 밝은 면 | 전체 배경 |
| `canvas-bottom` | `#000000` | 메인 섀시의 어두운 면 | 전체 배경 |
| `surface-top` | `#000000` | 돌출된 컨트롤 패널 | 패널 내부 |
| `surface-bottom` | `#000000` | 패널 깊이 표현 | 패널 내부 |
| `display-top` | `#000000` | 애널라이저/LCD의 밝은 면 | 디스플레이 전용 |
| `display-bottom` | `#000000` | 애널라이저/LCD의 어두운 면 | 디스플레이 전용 |
| `text-primary` | `#000000` | 제품명과 주요 값 | 높은 우선순위 텍스트 |
| `text-secondary` | `#000000` | 라벨과 눈금 | 보조 텍스트 |
| `value-text` | `#000000` | 수치와 단위 | 값 표시 전용 |
| `accent-primary` | `#000000` | 포인터와 활성 상태 | 좁고 집중된 영역 |
| `accent-secondary` | `#000000` | 애널라이저 대비색 | 시각화 전용 |
| `section-accent` | `#000000` | 섹션 식별선 | 필요한 제품에서만 사용 |
| `outline` | `#000000` | 패널과 디스플레이 경계 | 구조 표현 |
| `deep-shadow` | `#000000` | 홈과 접촉면의 물리적 깊이 | 낮은 불투명도 |
| `highlight` | `#000000` | 재질 반사광 | 낮은 불투명도 |

팔레트 규칙:

- UI 구현 전에 사용하는 모든 토큰의 색상을 지정하고, 쓰지 않는 선택 토큰은 `미사용`으로 기록한다.
- 모든 색상은 용도가 있어야 하며, 설명되지 않은 HEX 값을 코드 곳곳에 추가하지 않는다.
- 기본 비율은 섀시 60%, 표면 30%, 포인트 컬러 10% 이내로 유지한다.
- 주 포인트 컬러는 상태, 포커스, 포인터, 짧은 섹션 라인에 사용한다.
- 애널라이저 보조색은 사용할 수 있지만 컨트롤보다 강하게 보이면 안 된다.
- 일반 모니터 밝기에서 텍스트와 컨트롤 경계가 명확히 읽혀야 한다.
- 한 계열의 색상만 명도별로 반복하는 단조로운 팔레트를 피한다.

### 2.2 기존 디자인은 참고하되 그대로 복제하지 않는다

고정 목업 레퍼런스 경로:

`E:\Plugin Projects\Guide MD\Tools\Mockup`

모든 신규 플러그인 디자인과 기존 플러그인 리디자인은 작업을 시작하기 전에 위 폴더의 이미지
파일을 직접 열어 확인해야 한다. 이 확인은 선택 사항이 아니라 디자인 착수 게이트다.

- 작업 시점에 폴더에 들어 있는 모든 지원 이미지 파일을 확인한다. 최초 등록된 목록만 기억에 의존해 사용하지 않는다.
- 확인한 파일명을 브리프에 기록하고, 각 목업에서 유지할 요소와 수정할 요소를 분리한다.
- 핵심 메타포, 대표 장면, 정보 위계, 색상 역할, 재질, 깊이, 컨트롤 종류, 시간 변화 시각화와 UX 흐름을 분석한다.
- 목업은 방향과 판단 기준을 제공하는 자료이며 특정 제품의 배치, 그래픽과 브랜드를 그대로 복제하지 않는다.
- 폴더가 없거나 이미지를 열 수 없다면 목업 확인을 완료한 것으로 처리하지 않고 먼저 경로와 파일 상태를 확인한다.

하드웨어, 플러그인, 이미지 레퍼런스는 분위기, 재질, 밀도, 상호작용의 방향을 정하는 자료다.
레퍼런스의 배치를 그대로 재현하는 것이 목적이 아니다.

- 레퍼런스에서 유지할 컨셉과 수정할 문제를 브리프에 분리해 기록한다.
- 레퍼런스의 표면 스타일과 배치를 그대로 모사하지 않고 제품의 음악적 목적에 맞게 재해석한다.
- 시선 흐름, 크기, 정렬, 여백은 `5. 레이아웃과 시각적 위계`의 기준으로 판단한다.
- 정확한 모사보다 핵심 작업을 빠르게 이해할 수 있는 UX를 우선한다.

레퍼런스와 심미적 UX가 충돌하면 UX를 우선한다.

## 3. 디자인 철학과 TB 공통 시각 언어

**대원칙 — 최종 윈도우 최소화:** 필요한 기능, 판독성, 조작성과 포커스 표시를 모두 유지하는
범위에서 최종 플러그인 윈도우를 최대한 작게 만들기 위해 반복해서 배치와 크기를 줄인다.
특정 픽셀 크기를 모든 제품의 상한으로 강제하지 않는다. 컨트롤이 많은 제품은 필요한 행과
열만큼 창이 커질 수 있지만, 각 행·열은 compact 밀도를 유지하고 첫 시안의 넉넉한 크기를
그대로 승인하지 않는다.

13인치 맥북에서 100% 배율로 여러 플러그인을 함께 띄우는 실제 작업 장면을 기준으로 최종
크기를 선택한다. `TB_Disperser 600 × 300 px`는 메인 노브 4개, 작은 보조 노브 3개와
Hero Display 하나를 조밀하게 정리한 예시이며 범용 크기 제한이 아니다.
각 파트 사이의 간격은 가능한 한 작게 잡되 라벨, 값, 눈금과 포커스 링이 겹치지 않도록
스페이싱한다. 단순히 화면을 여유롭게 보이게 하려는 큰 셀과 빈 패널은 허용하지 않는다.
각 컨트롤러는 호버링 시 2초 후 해당 노브에 관련된 설명을 새로운 윈도우에 플로팅 해준다.
TB UI는 기능을 나열한 소프트웨어 패널이 아니라, 그래픽 디자이너가 의도적으로 만든 하나의
오디오 인스트루먼트처럼 보여야 한다. 사용자는 화면을 보는 데서 끝나지 않고 실제 아날로그
아웃보드의 노브와 스위치를 만지는 듯한 촉각적 경험을 받아야 한다.

사실적인 장식을 많이 넣는 것이 목표는 아니다. 사람이 만든 느낌은 일관된 조명과 재질,
손이 닿는 부품의 물리적 관계, 정돈된 눈금과 각인, 의도적으로 다듬은 미세 디테일에서 만든다.
무작위 노이즈, 과도한 스크래치, 목적 없는 낡음 효과로 제작감을 흉내 내지 않는다.

핵심 디자인 키워드는 다음과 같다.

- `Designer-authored`: 범용 컴포넌트의 조합이 아니라 제품 목적에 맞게 직접 설계하고 다듬은 화면
- `Tactile Instrument`: 보고 읽는 패널을 넘어 손으로 조작하고 싶게 만드는 촉각적 인터페이스
- `Analog Outboard`: 돌출된 컨트롤, 매입된 미터, 각인된 눈금이 만드는 물리 장비 경험
- `Macro-first`: 가장 중요한 음악적 결과와 첫 조작이 한눈에 보이는 위계
- `Final-window Minimization`: 기능 수에 맞는 최소 행·열만 사용하고 최종 창을 계속 줄이는 원칙
- `Semantic Color`: 색마다 파라미터, 상태, 신호 또는 경고 역할을 고정하는 방식
- `Direct Feedback`: 조작 결과와 시간에 따른 변화를 즉시 읽을 수 있는 피드백
- `Material Consistency`: 한 화면 안에서 조명, 거칠기, 베벨과 부품 재질이 같은 세계에 속하는 일관성

### 3.1 핵심 메타포와 대표 장면

각 플러그인은 음악적 결과를 설명하는 하나의 핵심 메타포를 먼저 정한다. 콘솔 채널, 광학식
계기, 공간 지도, 자기장처럼 사용자가 효과의 성격을 감각적으로 이해할 수 있는 이미지여야 한다.

- 제품의 핵심 결과를 대표하는 하나의 `Hero Control` 또는 `Hero Display`를 정한다.
- 첫 시선과 첫 조작은 Hero 영역으로 향하고, 정밀 조정은 주변이나 보조 패널에 배치한다.
- Hero 영역의 크기는 장식적 존재감이 아니라 사용 빈도와 음악적 중요도를 반영한다.
- 유틸리티형 제품처럼 정보 효율이 우선이라면 억지로 대형 비주얼을 만들지 않고, 가장 중요한 작업 영역을 대표 장면으로 삼는다.
- 서로 다른 시대와 도구의 메타포를 한 화면에 그대로 섞지 않는다. 네온 우주, 사실적 진공관 장비, 유리 패널 중 하나를 주재료로 정한다.
- 감성적인 이름이나 은유를 사용하더라도 짧은 기능 라벨, 값, 단위와 피드백으로 실제 역할을 확인할 수 있어야 한다.

### 3.2 색상 외 표현과 직접 제작 이미지 원칙

**직접 제작 원칙:** 배경, 노브, 슬라이더 등 UI에서 색상 표현 이외의 추가적인 재질감·깊이감·
시간에 따른 변화값·가시화를 위한 구분 표현이 필요할 때는 디자이너가 직접 이미지를 만들어 적용한다.

이 원칙은 섀시의 표면결, 노브 캡과 측면, 슬라이더 트랙과 핸들, 스위치, 베젤, 미터 페이스와
유리 반사, 상태 마스크, 시각화 오버레이에 적용한다. 단순한 색면과 기본 도형만으로 충분히
전달되는 요소까지 불필요하게 이미지로 만들 필요는 없다.
제품별 신규 이미지 에셋을 수량으로 강제하지 않는다. 코드 도형만으로 재질·상태·위계를 충분히
표현할 수 있으면 그것으로 완료할 수 있다. 우상단 공통 시그니처는 브랜드 정본이므로 제품별
신규 이미지나 재작도 실적으로 계산하지 않는다.

- 범용 텍스처나 생성 이미지를 보정 없이 그대로 사용하지 않는다. 최종 에셋에는 디자이너의 선택, 수정, 조명 정합과 실제 크기 검수가 반영되어야 한다.
- 재질 베이스와 시간에 따라 바뀌는 값, 라벨, 숫자, 포인터는 분리한다. 변화값을 배경 이미지에 고정하지 않는다.
- 기본, 활성, 눌림, 비활성 상태는 서로 다른 물건이 아니라 같은 부품의 상태 변화로 보여야 한다.
- 색각 차이와 저채도 환경에서도 구분할 수 있도록 색과 함께 형태, 위치, 선 굵기, 패턴, 명도 중 하나 이상을 사용한다.
- 직접 제작 에셋의 분류, 원본과 출력물 관리 기준은 `10.2 디자이너 제작 이미지 에셋`을 따른다.

### 3.3 재질, 조명과 깊이

- 섀시는 가장 뒤에 있고, 손이 닿는 노브와 스위치는 돌출되며, 미터와 디스플레이는 베젤 안으로 들어가야 한다.
- 한 화면의 주광 방향, 그림자 방향, 금속 입자 크기, 표면 거칠기, 베벨 깊이를 통일한다.
- 금속, 도장면, 고무, 유리처럼 재질이 달라질 때는 기능적 이유가 있어야 한다.
- 접촉 그림자, 림, 측면 두께와 반사광은 부품의 높이와 조작 가능성을 설명하는 데 사용한다.
- 텍스처와 반사광은 라벨, 값, 포인터, 포커스 상태의 판독성을 침범하지 않아야 한다.
- 사진처럼 보이는 정밀 묘사보다 실제 플러그인 크기에서 즉시 읽히는 물리적 관계를 우선한다.
- 정보를 담지 않는 장식용 액센트 라인은 두지 않는다. 제품명 아래 밑줄, 섹션 상단의
  컬러 스트라이프처럼 상태·값·경계 어느 것도 설명하지 않는 선은 화면을 여러 판때기로
  쪼개고 컨셉 컬러의 의미를 희석한다. 영역 구분이 필요하면 선이 아니라 매입 깊이와
  면의 명도 차이로 표현한다.

### 3.4 시간 변화와 시각 피드백

시간은 장식이 아니라 상태와 소리의 반응을 설명하는 디자인 재료다.

- 현재값, 사용자가 설정한 기준값, 목표값, 피크 또는 누적값, 경고 한계를 먼저 구분한다.
- 움직임의 방향, 범위, 속도는 실제 값의 변화와 일치해야 한다.
- 미터의 관성, 감쇠, 피크 홀드와 잔상은 읽기 쉽도록 제한적으로 설계하고 실제보다 변화량을 과장하지 않는다.
- 디자이너는 바늘, 마커, 점등 세그먼트, 상태 프레임, 마스크와 오버레이를 직접 설계하되 실제 값이 그 시각 상태를 결정하게 한다.
- 신호나 상태 변화가 없으면 측정 화면도 정지하거나 비어 있어야 한다. 측정값처럼 보이는 가짜 움직임을 추가하지 않는다.
- 장식 모션이 필요한 경우 측정 영역과 분리하고, 실제 데이터로 오해되지 않는 형태와 대비를 사용한다.

### 3.5 제품군 공통 요소와 플러그인별 요소

다음 요소는 TB 제품군에서 공통으로 유지한다.

- 기능상 필요한 경우에만 물리적 베젤 안에 들어간 애널라이저 또는 메인 디스플레이
- 평면 원이 아닌 돌출된 아날로그 스타일 노브와 물리 관계가 분명한 선형 컨트롤
- 중성 금속 재질과 대비되는 의미 기반 포인터 컬러
- 짧은 대문자 섹션명과 음악적 의미 중심의 파라미터명
- 하나의 최상단 가로줄에 놓인 좌측 굵은 고딕 계열 플러그인 이름과 우측 투명 배경
  Team Impulse Impact 공통 시그니처 물고기 로고
- 중앙 정렬 프리셋 브라우저와 그 오른쪽 저장 아이콘, Supporting 등급의 실행 취소·다시 실행
- 배경이 비치지 않는 불투명 컨트롤 패널
- 주요 컨트롤 가까이에 단위가 포함된 값 표시

플러그인별로 달라질 수 있는 요소:

- 핵심 메타포, Hero Control 또는 Hero Display
- 컨셉 팔레트, 재질의 세부 성격과 애널라이저 포인트 컬러
- 노브 크기 예외가 필요한 경우 그 대상과 제품상 이유
- 섹션의 수, 이름, 순서
- 필요한 경우에만 사용할 애널라이저 종류와 표시할 측정값
- 실제 작업 흐름에 필요한 컨트롤 밀도와 직접 제작 이미지 에셋

## 5. 레이아웃과 시각적 위계

### 5.1 헤더

- 헤더는 로고·제품명·프리셋 도구를 담는 **최상단 독립 랙 섹션**으로 분리한다. 본문 패널과
  같은 경계 안에 섞거나 애널라이저 위에 떠 있는 개별 카드처럼 만들지 않는다.
- 헤더 내부는 참고 UI의 top bar처럼 **한 줄짜리 수평 행**으로 구성한다. 같은 행 안에서
  `좌측 제품명 → 중앙 프리셋 도구 → 우측 Team Impulse Impact 공통 시그니처 로고` 순으로 읽혀야 하며,
  어느 하나도 두 번째 줄로 내리거나 별도 상·하단 strip으로 분리하지 않는다.
- 100% UI 배율에서 제품명 주 라벨, 프리셋 selector와 우측 `48 × 48 px` 시그니처 로고 슬롯의 시각 중심 Y
  차이는 최대 `6 px`로 제한한다. 제품명 아래의 작은 부제는 이 중심 계산에서 제외한다.
- 플러그인 이름은 좌상단에 굵은 고딕 계열 산세리프체로 두며 헤더에서 가장 강한 텍스트 신호가
  되어야 한다. 이름은 프리셋 텍스트보다 크고 밝아야 한다.
- 승인된 Team Impulse Impact 공통 시그니처의 **투명 누끼본**은 같은
  헤더 행의 우측 `48 × 48 px` 슬롯에 둔다. 제품명과 로고는
  양끝에 있어도 같은 수직 중심선과 같은 **브랜드 위계**에 속하며, 로고를 별도 위·아래 행이나
  독립 카드로 분리하지 않는다.
- 공통 시그니처는 `845 × 845` 원본 전체 canvas를 `48 × 48 px` 슬롯 안에 비율 유지·중앙
  정렬하고 `highResamplingQuality`로 그린다. 별도의 crop, canvas 확장, 재정규화와 임의 offset은
  적용하지 않는다.
- 고정 슬롯 안의 안전 여백이 부족해 로고가 잘린 것처럼 보이는 경우에도 로고나 슬롯을 옮기지
  않는다. 인접 Supporting 버튼 묶음의 간격·크기·위치를 먼저 압축한다.
- 로고의 유효 안전 영역은 `48 × 48 px` 슬롯 자체가 아니다. 인접 버튼의 실제 component
  bounds와 나사 외곽에 각각 최소 `4 px` 간격을 더한 영역을 제외한 뒤, 표시된 로고의
  `Bp=bbox(A>=1)`가 남은 영역 안에 들어가는지 확인한다. JUCE child 버튼은 parent `paint()`의
  로고보다 나중에 그려지므로 bounds가 겹치면 투명 슬롯 여백과 관계없이 로고가 가려진다.
  중심 고정 축소만으로 승인된 가독 크기를 유지할 수 없으면 로고를 더 줄이지 않고 인접
  Supporting 버튼 묶음의 간격·크기·위치를 먼저 압축한다. 로고 슬롯과 중심은 이동하지 않는다.
- 기본 우상단 물고기 로고는 제품 기능을 설명하도록 변형하지 않는다. 제품 의미는 본문 Hero
  Control, Hero Display, 라벨과 실제 상태 피드백에서 설명하고 공통 시그니처는 브랜드 식별만
  담당한다. 제품별 예외는 사용자 승인과 브리프의 `10.1.1` 항목 지정이 모두 있을 때만 허용한다.
- 기본 우상단 로고는 승인된 공통 시그니처 완성 이미지를 한 번만 그린다. 명시 승인 예외가 없는
  상태에서 소품·분신·왜곡·기준선·색 마스크를 원본이나 런타임 코드에 추가하지 않는다.
- 헤더 양 끝에는 랙 장착을 연상시키는 작은 나사를 같은 높이에 둔다. 나사는 조작부보다 어둡고
  작아야 하며 버튼, 상태등 또는 포커스 대상으로 오인되지 않아야 한다.
- 헤더에 별도의 `TB SOUND` 텍스트를 표시하지 않는다.
- 프리셋 브라우저 자체의 중심은 에디터 가로 중심과 일치한다. Undo/Redo가 추가되어도 프리셋
  중심을 밀어내지 않으며, 저장은 프리셋 다음/이전 묶음의 오른쪽에 놓는다.
- 좁은 에디터에서도 프리셋 도구를 제품명·로고 아래로 줄바꿈하지 않는다. 최소 글꼴·아이콘·터치
  영역을 지킨 상태에서 좌우 여백과 selector 폭을 먼저 줄이고, 그래도 맞지 않으면 에디터 폭을
  넓힌다.
- 실행 취소와 다시 실행은 저장 뒤의 Supporting 도구로 배치하되 우상단 브랜드 로고와 경쟁하지 않는다.
- 실행 취소는 정확히 `←` (`U+2190 LEFTWARDS ARROW`), 다시 실행은 정확히
  `→` (`U+2192 RIGHTWARDS ARROW`)를 사용한다. 화살표 몸통은 곧은 수평선이어야 하며
  `↶`/`↷`, `↩`/`↪`, `⟲`/`⟳` 같은 곡선·hooked·circular 문자나 손그림 Path로 대체하지 않는다.
  두 기호는 같은 typeface·크기·bounds로 렌더링하며 기준 Windows 구현은 `Segoe UI Symbol` 16 px다.
- 구현 후 실제 캡처에서 좌우가 뒤집히지 않았는지 반드시 눈으로 확인한다. 좌우 반전은 코드에서
  부호 하나로 뒤집히기 쉬우며 컴파일과 자동 테스트로는 잡히지 않는다.
- 플러그인 이름과 우측 로고는 같은 최상위 브랜드 위계와 같은 행을 공유한다. 중앙 프리셋은
  탐색 도구로서 대비가 한 단계 낮을 수 있지만 같은 가로 헤더 행을 벗어나지 않는다.

#### 5.1.1 공통 프리셋 브라우저와 저장 구조

- 모든 플러그인은 기능 수와 관계없이 헤더 중앙에 프리셋 브라우저를 둔다. 기존 프리셋 체계가
  없는 단순 유틸리티도 최소 하나의 읽기 전용 `Init` Factory 상태와 User 저장·불러오기를
  제공하며, 빈 장식 셀이나 동작하지 않는 버튼으로 요구를 대신하지 않는다.
- 헤더 중앙 프리셋 영역은 `[이전] [프리셋 드롭다운] [다음] [플로피 디스크 저장] [← 실행 취소] [→ 다시 실행]`
  순서로 배치한다. 드롭다운의 중심은 플러그인 전체 중심에 고정한다.
- 저장 버튼은 문구나 글꼴 문자 대신 해상도와 폰트에 의존하지 않는 벡터 플로피 디스크 아이콘으로 그린다.
- 프리셋의 탐색, 불러오기, 저장 위치, 정렬, 스캔, 피드백 동작은 `9.2 공통 프리셋 탐색과 저장 UX`에서 관리한다.

### 5.2 애널라이저 또는 메인 디스플레이

- 애널라이저나 메인 디스플레이는 기능상 필요하거나 조작 판단에 실질적인 정보를 줄 때만 표시한다.
- 단순한 공간 채우기, 장식 애니메이션, 노브 값을 중복 표시하는 용도로 추가하지 않는다.
- 필요하지 않다면 디스플레이를 생략하고 그 공간을 컨트롤의 가독성과 컴팩트한 창 크기에 사용한다.
- 사용하는 경우 화면 상단에 배치하고 하단 컨트롤 영역과 좌우 폭을 의도적으로 맞춘다. 이때
  컴포넌트 bounds가 아니라 **실제로 그려진 외곽 베젤의 좌우 edge**가 컨트롤 보드의 그려진
  외곽 edge와 일치해야 한다.
- 내부는 불투명 LCD 스타일로 만들고 물리적인 베젤을 표현한다.
- 시각화의 정보 구분과 그래픽 규칙은 `7. 시각화 표현 기준`, 시간 동작은 `9.3 애널라이저 피드백 UX`에서 관리한다.

### 5.3 컨트롤 영역

- 애널라이저가 있으면 그 아래에, 없으면 헤더 바로 아래에 전체 폭을 활용한 불투명 패널을 배치한다.
- 장식 배경 위에 반투명 컨트롤 패널을 사용하지 않는다.
- 섹션 간 간격과 전체 외곽 여백을 일정하게 유지한다.
- 내부 DSP 클래스명이 아니라 음악적 역할과 작업 흐름으로 그룹을 나눈다.
- 반복되는 그룹은 손의 기억을 위해 구조를 통일한다.
- 카드 안에 카드를 넣는 중첩 구조를 사용하지 않는다.
- 하나의 공용 보드 안에서 음악적 역할이 같은 위계의 섹션을 나눌 때는 같은 광원·베벨·그림자
  깊이를 가진 얕은 양각 peer panel을 사용할 수 있다. 네 패널 중 하나만 다른 높이로 보이거나
  그 안에 다시 카드를 넣지 않으며, 애널라이저와 LCD는 반대로 매입된 깊이를 유지한다.

#### 5.3.1 정보·조작 위계와 컨트롤 노출

위계는 단순히 노브 크기 차이로 만들지 않는다. 먼저 사용자가 보아야 하는 순서와 조작해야 하는
순서를 정하고, `위치와 읽기 순서 → 그룹과 경계 → 대비와 여백 → 크기` 순으로 표현 수단을
선택한다. 중요한 컨트롤도 같은 크기의 부품을 사용할 수 있으며, 이 경우 앞쪽 배치, 그룹 중심,
짧은 라벨과 명확한 상태 피드백으로 우선순위를 만든다.

| 단계 | 역할 | 디자인 원칙 |
| --- | --- | --- |
| 1. Hero | 제품의 핵심 음악적 결과 또는 판단 화면 | 한 화면에 하나만 두고 첫 시선이 향하는 위치와 면적을 부여한다. 장식이 아니라 실제 작업을 설명해야 한다. |
| 2. Structure | 음악적 작업 순서에 따른 섹션과 신호 흐름 | 하나의 보드 또는 명확한 큰 구획으로 정리하고, 짧은 제목과 필요한 경계만 사용한다. |
| 3. Primary | 첫 결과를 만드는 소수의 주요 조작 | 자연스러운 읽기 순서와 그룹 중심에 둔다. 제품상 이유 없이 모두 대형 노브로 만들지 않는다. |
| 4. Standard | 자주 사용하는 세부 조정 | 같은 크기, 라벨, 값 위치와 조작 문법을 유지해 빠르게 비교할 수 있게 한다. |
| 5. Supporting | 프리셋, 저장, Undo/Redo와 마무리 유틸리티 | 헤더 또는 독립된 얇은 strip에 두어 음향 조작보다 먼저 보이지 않게 한다. |
| 6. Preset-only / Internal | 프리셋 캐릭터에는 필요하지만 일반 조작 가치가 낮은 값 | 일반 화면에서 숨기고 브리프에 이유, 프리셋 제어 방식과 상태 호환 범위를 기록한다. |

일반 화면에 컨트롤을 노출하려면 다음 중 하나 이상을 만족해야 한다.

- 이름만으로 사용자가 들리는 결과를 예상할 수 있다.
- 반복해서 직접 조정할 가능성이 높다.
- Hero Display 또는 다른 핵심 피드백을 이해하고 수정하는 데 필요하다.
- 독립적인 음악적 결과가 있으며 이미 노출된 매크로나 모드와 역할이 겹치지 않는다.

반대로 구현 세부에 가까운 값, 다른 매크로에 강하게 종속된 값, 드물게만 조정하는 값,
동시에 노출할 때 과처리와 선택 피로를 만드는 값은 `Preset-only / Internal` 후보로 검토한다.
기존 자동화와 프리셋 호환이 필요한 제품에서는 UI 컴포넌트만 숨기고 파라미터 ID, 상태 복원과
DSP 경로는 계획된 호환성 중단 버전 전까지 보존한다.

섹션 밀도를 조정하는 순서는 다음과 같다.

1. 컨트롤을 DSP 클래스가 아니라 들리는 결과에 맞는 섹션으로 이동한다.
2. 한 행이 답답하면 같은 수의 칸으로 억지 압축하지 않고 `Tone / Motion`, `Timing / Shape`처럼 작업 단위가 다른 행으로 나눈다.
3. 성긴 섹션은 관련 컨트롤을 중심 정렬하고, 전체 보드나 창을 줄일 수 있는지 검토한다.
4. 위 노출 기준을 통과하지 못한 컨트롤만 preset-only로 내린다.

빈 칸을 채우기 위한 새 노브, 장식 셀 또는 의미 없는 대칭은 추가하지 않는다. 반대로 긴 라벨,
값, 포커스 링이 겹치는 상태에서 한 줄 실루엣을 유지하려고 Standard 노브를 축소하지 않는다.
행 분리는 같은 개수로 나누는 것이 아니라 실제 작업 단위와 시선 흐름을 기준으로 정한다.
위계를 위한 여백은 섹션 제목, 행과 그룹 사이의 로컬 gutter로 제한한다. Standard 셀 하나가
들어갈 큰 빈 띠는 허용하지 않으며 `5.5`의 패널 사용 가능 영역 85% 점유 기준을 유지한다.

### 5.4 노브 크기 위계

모든 컨트롤은 작업상 역할을 `Primary`, `Standard`, `Supporting`으로 분류하되 역할 등급과
노브 크기 토큰은 별도로 기록한다. 역할 등급이 자동으로 시각 크기 차이를 의미하지는 않는다.
기본 노브는 100% UI 배율에서 외곽 눈금 기준 지름 `41 px`의 Standard 크기를 사용하며
그림자는 이 지름에 포함하지 않는다. 별도의 제품상 이유가 없다면 역할 등급과 관계없이 모든
연속 파라미터 노브를 정확히 같은 크기로 만든다.
시각적 노브 지름과 `Slider` 컴포넌트 또는 마우스 조작 영역의 크기는 구분한다. 조작성을
확보한다는 이유로 보이는 노브나 컨트롤 셀까지 크게 만들지 않는다.

| 크기 토큰 | 지름 | 사용 조건 |
| --- | --- | --- |
| Standard | `41 px` | 모든 연속 파라미터의 기본값 |
| Enlarged | Standard보다 큼 | 단일 Primary 매크로를 강조해야 하는 이유를 제품 설계에 기록한 경우만 사용 |
| Compact | `27–33 px` | 하단·우측의 얇은 보조 또는 마무리 모듈이며 작은 값창으로도 판독 가능한 경우 |

노브 배치 규칙:

- 이유가 기록되지 않은 크기 차이는 만들지 않는다. 출력, 믹스, 트림도 임의로 축소하지 않는다.
- Primary라도 독립된 Final strip 안에서 작업 순서가 명확하고 Standard 크기가 전체 보드의
  밀도를 해치는 경우 Compact를 사용할 수 있다. 브리프에 축소 이유, 값 판독 방식과 실제
  마우스 조작 영역을 기록한다.
- 크기 위계를 사용하는 예외에는 시각 크기뿐 아니라 실제 마우스 조작 영역도 함께 맞춘다.
- 자주 쓰는 노브를 자연스러운 시선 경로와 그룹 중심에 둔다.
- 연관된 컨트롤은 하나의 작업으로 인식될 만큼 가깝게 배치한다.
- 억지 대칭 때문에 중요도가 약해지거나 빈 공간이 생기면 비대칭 배치를 허용한다.
- 실제 플러그인 크기에서 라벨, 노브, 값 표시창 간격을 확인한다.
- Standard 노브의 기본 `Slider` bounds는 값창을 포함해 `80–90 × 60–66 px`, 값창은
  `60–64 × 16–18 px`에서 시작한다.
- Standard 노브 중심 간격은 `90–100 px`, 인접 `Slider` bounds 사이의 실제 빈 간격은
  `6–12 px`를 기본 범위로 한다. 긴 라벨 때문에 이 범위를 넘기면 fitted text나 줄임 이름을
  먼저 검토하고, 그래도 답답하면 필요한 최소량만 균일하게 늘린다.
- 한 노브마다 큰 카드나 넓은 독립 패널을 만들지 않는다. 같은 역할의 노브는 하나의 조밀한
  행 또는 그룹 안에서 셀을 공유한다.

### 5.5 컴팩트한 창과 컨트롤 가독성

- 필요한 컨트롤이 읽히는 가장 작은 창을 먼저 설계한다. 큰 캔버스에 컨트롤을 흩어 놓은 뒤
  남은 공간을 장식으로 채우는 순서를 사용하지 않는다.
- 같은 단계의 파라미터 라벨과 값은 같은 글자 크기를 사용한다. 100% 배율 시작값은 메인
  라벨·값 `10–10.5 px`, Supporting 라벨·값 `8.5–9.5 px`, 섹션명 `8.5–10.5 px`,
  보조 문구 `8–9.5 px`다. `14 px` 이상은 제품명이나 의도적으로 강조한 Hero 정보에만 쓴다.
- 패널 외곽 패딩은 `10–14 px`, 반복 컨트롤 사이의 수평 빈 간격은 `6–12 px`에서 시작한다.
- 라벨·컨트롤·값 표시와 다음 행의 시각 bounds는 서로 교차하지 않는다. 100% 배율에서
  라벨–컨트롤과 값 표시–다음 행 사이는 최소 `4 px`, 반복 행·그룹 사이는 `8–12 px`의
  실제 빈 간격을 유지하고 포커스 링까지 포함한 렌더링으로 확인한다.
- 그룹 경계선은 그 경계 안의 컨트롤이 실제로 공유하는 기능 단위와 일치해야 한다. 독립된
  보조 처리 하나를 구분할 때는 전체 행·열을 관통하는 선으로 인접 컨트롤까지 별도 그룹처럼
  보이게 하지 않고, 해당 구획의 경계를 외곽 패널 선에 연결해 소속을 명확히 한다.
- 가장 긴 라벨·값, 포커스 링, 조작 영역 또는 그룹 구분에 실제로 필요하면 전체 그리드
  스페이싱을 약간 늘리는 것을 허용한다. 보통 각 간격을 `2–4 px`씩 균일하게 늘린 후보부터
  비교하며, 문제를 해결하는 가장 작은 증가량을 채택한다. 이 경우 최종 윈도우가 그 합계만큼
  커지는 것은 최종 윈도우 최소화 원칙과 충돌하지 않는다.
- 위 증가는 가독성과 조작성을 위한 예외다. 노브나 장식의 존재감을 키우거나 목적 없는 빈
  공간을 만들기 위한 확대에는 사용할 수 없으며, `6–12 px`는 기본 시작 범위이지 절대 상한이
  아니다.
- `10 px` 이하의 작은 텍스트와 대문자 라벨에는 음수 자간이나 과도한 수평 축소를 사용하지
  않는다. 글자가 붙어 보이면 먼저 자간·셀 폭·행 높이를 확보하고 fitted text보다 짧은 명칭을
  우선 검토한다.
- 상시 UI 카피는 제품명, 섹션명, 조작명, 현재 값, 사용자가 판단해야 할 측정값과 행동 가능한
  상태로 제한한다. `fully wet`, 오버샘플링 배수, 내부 lookahead, 측정 표준·알고리즘명,
  stereo link, 신호 경로, DSP 모드, 빌드·버전처럼 조작이나 판단을 바꾸지 않는 구현·검증
  사양을 헤더·패널·footer의 장식 문구로 노출하지 않는다. 필요한 사양은 매뉴얼, 릴리즈 문서,
  호스트 메타데이터 또는 해당 조작의 간결한 툴팁으로 이동한다.
- 표준적인 hover·값 입력 방법을 설명하는 지속형 도움말 행은 실제 발견성 문제가 확인된
  경우에만 사용한다. 디버그성·중복 카피를 제거했다면 그 행을 빈 장식으로 남기거나 다른
  기술 문구로 대체하지 않고, 확보한 공간을 패널 또는 최종 윈도우 축소에 반영한다.
- 컨트롤 그룹은 패널의 사용 가능 가로·세로 영역을 각각 최소 `85%` 사용해야 한다. Standard
  컨트롤 셀 하나가 들어갈 정도의 미사용 띠가 남으면 의도적 여백이 아니라 과대 레이아웃으로
  판정한다.
- 가장 긴 프리셋명, 라벨, 최소·최대 값, 키보드 포커스 링을 실제 렌더링해 겹침이 없음을
  확인한다. 글자를 키우기 위해 창을 먼저 키우지 않고 fitted text, 짧은 라벨과 값 형식을
  우선 검토한다.
- 첫 후보에 큰 빈 띠나 과도한 셀이 있으면 가로와 세로를 각각 약 `70%`로 줄인 안을
  교정 출발점으로 만들어 비교한다. 컨트롤이 많다면 무리하게 같은 크기로 압축하지 않고
  `5.4`의 셀 밀도를 유지한 채 필요한 최소 행·열만 추가한다. 배경 장식은 비례 축소할 수
  있지만 자식 컨트롤은 전역 transform에 맡기지 않고 재배치하며, `41 px` Standard 노브,
  `24 px` 헤더 버튼과 위 글꼴 하한은 유지한다.

이 기준에서 메인 `Slider` bounds 사이의 빈 간격은 `9 px`, 노브 중심 간격은 `99 px`다.
Supporting 컨트롤은 전체 y축을 독점하지 않고 메인 행 오른쪽의 작은 모듈 안에 묶는다.
이 예시에서 `FREQUENCY LFO`는 왼쪽 정렬한 부모 섹션 제목이고 `TYPE`은 상단 로터리의
자식 파라미터 라벨이다. 좁은 Type 값창의 UI 표시만

로터리 중심 y는 같아야 한다. 특히 오른쪽 값창을 가진 inline
Type Slider의 전체 bounds 중앙을 로터리 대칭축으로 착각하지 않는다.

## 6. 아날로그 컨트롤과 재질 표현 기준

### 6.1 노브

노브는 패널 위로 돌출되어 손으로 잡을 수 있는 실제 부품처럼 보여야 한다.

필수 시각 레이어:

1. 패널과 맞닿는 부드러운 접촉 그림자
2. 물리적 두께를 보여주는 아래쪽 측면
3. 밝은 면과 어두운 면이 분리된 상단 림
4. 단순 방사형이 아닌 비대칭 표면 조명
5. 약한 원형 가공결 또는 재질 텍스처
6. 상단 하이라이트와 하단 차광
7. 홈이 파인 듯한 어두운 바탕과 제품 고유 `accent-primary` 포인터
8. 별도 베벨이 있는 작은 중앙 캡
9. 몸체 바깥의 각인된 듯한 눈금

- 가장 작은 노브에서도 텍스처가 뭉치거나 지저분해지지 않아야 한다.
- 그림자와 측면 두께는 노브 지름에 비례시킨다.
- 아날로그 기본 스타일에 네온 진행 링을 사용하지 않는다.
- 값의 진행량을 외곽 arc로 표시할 때는 전체 범위를 낮은 대비의 홈으로 두고, 시작점부터 현재
  값까지만 제품 포인트 컬러로 채운다. arc는 포인터와 함께 현재값을 보강하되 노브 몸체보다
  먼저 보이는 발광 링이 되어서는 안 된다. 작은 Compact 노브는 같은 굵기를 비례 축소해
  사라지게 하지 말고 실제 크기에서 읽히는 최소 굵기를 별도로 정한다.
- 외곽선 하나와 그라데이션 하나뿐인 평면 원으로 끝내지 않는다.
- 프레임 또는 상태별 이미지 에셋을 사용할 경우 중심점, 외곽 크기와 접촉 그림자가 상태 사이에서 흔들리지 않아야 한다.

### 6.2 슬라이더와 선형 컨트롤

연속값의 위치, 범위, 시간축 또는 Dry/Wet 관계를 선형으로 읽는 편이 빠를 때 슬라이더를 사용한다.

- 트랙은 패널에 파인 홈처럼, 핸들은 그 위를 움직이는 별도 부품처럼 표현한다.
- 채워진 범위와 남은 범위는 색뿐 아니라 홈의 깊이, 명도, 표면결 또는 경계선으로 함께 구분한다.
- 핸들에는 접촉 그림자, 측면 두께와 명확한 기준점을 두어 현재 위치를 읽을 수 있게 한다.
- 양극성 슬라이더는 중앙 디텐트와 양쪽 방향을 명확히 표시하고, 범위 슬라이더는 두 핸들의 역할을 혼동하지 않게 한다.
- Dry/Wet `MIX`는 최소점부터 현재값까지 굵은 amount track을 채우고, 양극성 `OUTPUT`은
  0 dB 기준점부터 현재값 방향으로 채운다. 두 컨트롤은 같은 트랙·핸들 재질을 사용하되
  OUTPUT의 0 dB marker와 detent를 생략하지 않는다.
- 트랙, 핸들, 눈금판에 재질과 깊이가 필요하면 디자이너가 각각의 이미지 에셋과 상태 변형을 직접 제작한다.
- 일반 웹사이트의 진행 막대처럼 보이는 표현은 디지털 계기라는 제품상 이유가 있을 때만 사용한다.

### 6.3 스위치와 버튼

- 토글 스위치는 레버의 축과 물리적 방향으로 상태를 보여주며 색 변화에만 의존하지 않는다.
- 누름 버튼은 눌린 상태에서 하이라이트와 그림자 관계가 안쪽으로 이동한 것처럼 보여야 한다.
- 활성광은 상태에 따라 바뀌고, 재질 반사광은 상태와 무관하게 같은 위치를 유지한다.
- 독립 모듈을 바이패스할 수 있는 제품은 각 섹션 제목선의 같은 위치, 기본적으로 우측 끝에
  작은 바이패스 스위치를 둔다. 바이패스 중에도 설정값은 보존하고 읽을 수 있게 유지하되,
  영향을 받는 컨트롤군은 감광하며 스위치 자체는 계속 조작 가능해야 한다.
- 모듈 바이패스 상태는 색 변화뿐 아니라 눌림, 외곽선, `BYP` 또는 전원 형태처럼 비색상
  단서로도 구분한다.
- 나사, 통풍구, 홈과 패널 이음선은 실제 구조나 구획 의도가 있는 위치에만 사용해 컨트롤로 오인되지 않게 한다.

### 6.4 컨트롤 재질 일관성

- 모든 컨트롤의 조명 방향과 관찰 시점을 통일한다.
- 섀시, 노브, 고무, 유리와 크롬은 하이라이트의 폭과 선명도로 재질을 구분하며 색 차이에만 의존하지 않는다.
- 같은 부품은 어느 섹션에 있더라도 같은 재질, 높이와 상태 표현을 유지한다.
- 무채색으로 보아도 돌출, 매입, 눌림과 조작 가능 여부를 구분할 수 있어야 한다.
- 재질 표현은 디자이너의 제작감을 만들되 값, 라벨과 상태보다 먼저 보이지 않아야 한다.

## 7. 시각화 표현 기준

시각화를 설계하기 전에 다음 다섯 등급 중 하나로 분류한다. 등급을 섞으면 장식이 측정값처럼
보이거나 실제 상태가 단순 분위기 연출처럼 보일 수 있다.

1. `측정 시각화`: 실제 오디오 또는 DSP 측정값을 축, 단위, 눈금, 미터로 표시한다.
2. `파라미터 예측 시각화`: 현재 파라미터, 호스트 템포와 DSP 토폴로지로 앞으로 만들어질 결과를 결정론적으로 계산해 표시한다. 실제 입력을 분석하는 화면으로 보이게 하지 않는다.
3. `상태 기반 은유 시각화`: 실제 입력, 엔벌로프, 게인 리덕션, 파라미터, LFO 또는 호스트 상태를 밝기, 팽창, 열감, 입자 밀도처럼 감각적으로 번역한다. 정밀 측정을 주장하지 않는다.
4. `장식·재질 표현`: 브러시 결, 인쇄 편차, 미세 입자와 유리 반사처럼 제품의 물성을 만드는 정적 요소다.
5. `상호작용 피드백`: 호버, 누름, 포커스, 토스트처럼 사용자 입력에 의해 시작되는 짧은 상태 전환이다.

### 7.1 공통 시각 원칙

- 표시 정보가 설정값, 순간값, 누적·피크값, 목표·기준값, 경고·한계 중 무엇인지 먼저 정의한다.
- 서로 다른 정보는 색뿐 아니라 선 굵기, 형태, 채움, 위치, 패턴과 라벨로 구분한다.
- 그리드와 눈금은 실제 데이터보다 약하게 표시한다.
- 변화하는 바늘, 마커, 점등 구간, 파형과 흔적은 정적 재질 베이스와 분리된 시각 레이어로 설계한다.
- 한 화면 안의 시각 강도는 `사용자가 먼저 판단할 기준점 → 현재값 또는 첫 결과 → 이후 변화와
  반복 → 범위·감쇄 영역 → 그리드와 장식` 순으로 낮춘다.
- 상태 기반 은유의 원천 상태, 시각 속성, 매핑 방향과 범위, 중립 상태, 스무딩 시간을 브리프에 기록한다.
- 상태 기반 은유에는 정밀 측정으로 오해될 수 있는 단위, 교정 눈금과 계측기 바늘을 사용하지 않는다.
- 파라미터 예측 시각화는 DSP와 같은 식으로 계산되는 축과 단위만 사용할 수 있다. 추정 또는
  클램프 구간은 별도로 표시하고, 실제 오디오 측정이나 입력 레벨처럼 보이는 파형을 만들지 않는다.
- 장식·재질 표현은 오디오나 상태에 연결되지 않는다면 정적으로 유지한다.
- 상호작용 피드백은 상태가 끝난 뒤 반복하지 않고 측정값처럼 표현하지 않는다.

### 7.2 주파수 응답형 애널라이저

- 애널라이저는 장식 화면이 아니라 측정값과 처리 결과를 읽는 화면처럼 보여야 한다.
- 오디오 주파수 축은 로그 스케일을 기본으로 하며 양 끝의 숫자가 겹치지 않아야 한다.
- 입력 스펙트럼과 필터 응답은 동일한 주파수 좌표에 정확히 겹친다.
- 입력, 출력, 감쇄, 다이나믹과 스펙트럴 레이어는 역할이 다른 색과 선 스타일로 구분한다.
- 영향을 받는 중첩 영역은 원래 응답을 가리지 않는 보조색, 패턴과 투명도로 표시한다.
- 표시 한계에서 곡선이 잘릴 때 불필요한 연결선이나 중첩 착시가 생기지 않게 한다.
- `TB_MultiBandCompressor` 제품 예외: 같은 log-frequency X 위에서 원본 INPUT은 독립 `0…-96 dBFS` Y mapping과 top `0 dBFS` caption을 사용하고 response/node는 물리적 중앙 0 dB를 유지한 piecewise `-48…+12 dB` mapping을 사용한다. Actual DSP response는 plot 전폭의 `#817C66`, alpha `1.0`, `3.0 px` rounded stroke 하나이며 idle/outside-band 구간은 0 dB datum, active 구간만 위·아래로 변형된다. Range maximum은 node Y로만 표시하고 별도 fixed datum, configured Range/red actual overlay, gain fill/shadow/gradient는 사용하지 않는다. Custom editor 표시명은 정확히 `Multi Band Compressor`이고 M/B/C는 `#7088B2/#4F805F/#C65350`이다. Stereo Link host/state/DSP는 보존하지만 custom editor `LINK` UI는 숨긴다.
- 표시 조건, 시간 동작과 실제 파라미터의 의미 일치는 `9.3 애널라이저 피드백 UX`에서 관리한다.

### 7.3 파라미터 예측형 타임라인과 맵

- 원본 기준점과 첫 결과를 가장 굵고 높은 대비로 표시한다.
- 좌우 채널, 정방향·귀환 또는 서로 다른 경로는 위치를 우선하고 색과 선 스타일을 보조 단서로 사용한다.
- 이후 반복은 세대가 늦어질수록 선 굵기, 명도 또는 불투명도를 단계적으로 낮춘다.
- decay, 분산, 가능한 발생 범위는 첫 event marker보다 약한 면 또는 삼각형으로 표시한다.
- 축, lane guide와 그리드는 신호와 감쇄 영역보다 약한 중성색으로 두며 제품 포인트 컬러를 사용하지 않는다.
- 파라미터 조작 중에는 오디오 분석 주기를 기다리지 않고 예측 결과를 갱신한다. 원천 상태에 없는
  무작위 grain, shimmer 또는 자율 애니메이션을 추가하지 않는다.
- 표시 범위 밖의 결과는 잘라 없애기보다 끝점 클램프, overflow 표식 또는 라벨로 구분한다.

## 8. 라벨, 값, 컨트롤

- `AMOUNT`, `RANGE`, `SPACING`처럼 짧고 결과 중심인 이름을 사용한다.
- 사용자가 알 필요 없는 구현 용어를 노출하지 않는다.
- 값 표시에는 `Hz`, `%`, `dB` 같은 단위를 포함한다.
- 단일 연속값은 노브를 기본으로 사용한다. 위치, 범위, 시간축 또는 두 값의 비율을 선형으로 읽는 편이 빠르면 `6.2` 기준의 슬라이더를 사용한다.
- 2개 선택지는 토글 또는 분할 스위치, 3~4개의 순서 있는 선택지는 스텝 노브를 우선한다.
  항목이 많거나 이름을 비교해 골라야 할 때만 드롭다운 메뉴를 사용한다.
- 실행 취소와 다시 실행에는 익숙한 아이콘과 툴팁을 사용한다.
- 섹션 라벨은 작고 단정한 대문자로 표시한다.
- 가장 긴 라벨과 값도 레이아웃 크기를 흔들지 않고 들어가야 한다.

## 9. UX 가이드

UI 디자인 기준은 컨트롤이 어떻게 보이는지를 정의하고, UX 기준은 사용자의 입력에 어떤 순서와 상태 변화로 반응하는지를 정의한다. 상호작용 동작, 피드백, 오류 복구 규칙은 이 장에서 별도로 관리한다.

### 9.1 공통 상호작용 원칙

- 자주 사용하는 조작은 현재 화면 안에서 한두 단계로 끝나야 한다.
- 드래그, 휠, 클릭으로 변경되는 값은 화면과 실제 DSP 상태에 즉시 반영한다.
- 호스트 자동화, 프로젝트 상태 복원과 외부 제어로 바뀐 파라미터도 DSP와 UI에 즉시 같은 값으로
  반영한다. 외부 값의 화면 반영이 새 편집 gesture나 Undo 항목을 만드는 피드백 루프를 만들지 않는다.
- 저장, 프리셋 변경, 모드 전환처럼 상태가 바뀌는 조작은 성공 또는 실패 여부를 명확히 알린다.
- 실행 취소 가능한 변경과 파일 덮어쓰기처럼 복구 조건이 다른 동작을 같은 피드백으로 처리하지 않는다.
- 일시적인 안내는 오디오 작업을 막지 않아야 하며, 사용자의 판단이 필요한 오류만 명시적으로 닫게 한다.
- 키보드 포커스는 보이게 표시하되 DAW 단축키를 가로채는 전역 키 바인딩을 만들지 않는다. 특히 `Space`는 DAW transport에 양보하며, 플러그인 컨트롤이 이를 소비하거나 팝업을 열지 않는다.
- 핵심 기능은 숨은 제스처에만 의존하지 않는다. 보조 제스처는 툴팁이나 상태 표시로 발견 가능하게 만든다.

### 9.2 공통 프리셋 탐색과 저장 UX

- 별도의 `Load` 버튼은 두지 않는다. Factory 및 User 프리셋의 선택과 불러오기는 하나의 프리셋 드롭다운에서 처리한다.
- 둘 이상의 프리셋 폴더 또는 그룹이 있는 뱅크는 첫 단계에 논리 폴더만 표시하고, 각 하위 메뉴에 해당 프리셋을 표시하는 `폴더/그룹 > 프리셋` 2단계 구조를 사용한다. 그룹 헤딩 뒤에 모든 프리셋을 하나의 긴 평면 목록으로 나열하지 않는다.
- 브리프에 Factory 목표 개수, 논리 폴더 이름과 순서, 폴더별 quota를 기록한다. 대형 뱅크의
  개수를 늘릴 때 이름, Mix/Output 또는 한 값만 바꾼 사실상 중복으로 quota를 채우지 않는다.
- 같은 Factory 그룹은 뱅크에서 연속 배치하거나, UI가 그룹명을 기준으로 항목을 수집해 하나의
  하위 메뉴로 합쳐야 한다. 배열의 우연한 인접성에 의존하면서 같은 이름의 폴더를 여러 번 만들지 않는다.
- Factory leaf 이름과 메뉴 ID는 전체 뱅크에서 고유해야 하며, 그룹 순서·quota와 모든 그룹
  경계의 이전/다음 이동을 데이터 기반으로 검증한다.
- Factory의 제품별 그룹과 `USER`는 논리 폴더로 취급한다. 논리 폴더는 UI 탐색 구조이며 User 디스크 하위 폴더를 뜻하지 않는다.
- 현재 프리셋 이름은 항상 읽을 수 있어야 하며, 이전·다음 버튼은 현재 정렬 순서에서 한 단계씩 이동한다.
- 스캔형 User 뱅크의 이전·다음 순서는 Factory 그룹 선언 순서와 각 그룹 내부 순서를 평탄화한 뒤,
  정렬된 User 항목을 잇는다. 그룹 경계에서도 탐색이 끊기지 않는다.
- 파일 선택형 legacy API를 보존한 제품은 User 파일 목록을 소유하지 않으므로 이전·다음이 Factory
  항목 안에서만 순환할 수 있다. 이때 현재 불러온 User 상태를 화살표를 누르기 전까지 임의로
  바꾸지 않으며, 브리프에 legacy 동작과 스캔형 전환 조건을 기록한다.
- 첫 항목과 마지막 항목 사이는 순환한다. 길게 누르면 연속 탐색할 수 있지만 자동 재생이나 시간 기반 자동 전환은 사용하지 않는다.
- Factory 프리셋은 플러그인 내부의 읽기 전용 항목으로 유지한다.
- 새 제품과 기존 프리셋 경로가 없던 제품의 User 프리셋 표준 위치는 사용자 문서 폴더의
  `{제품명}/Presets/User`이며 제품별 확장자를 사용한다. 정확한 경로와 확장자는 제품 브리프에
  기록하고, 폴더가 없으면 에디터를 열 때 자동 생성한다.
- 이미 릴리즈된 제품의 User 프리셋 경로를 헤더·시각 디자인 롤아웃에 묶어 조용히 이동하지 않는다.
  표준 위치로 옮길 때는 기존 위치를 계속 읽는 dual-read, 충돌 처리, 쓰기 위치와 복구 방법을
  별도의 프리셋 마이그레이션으로 승인·검증한다. 마이그레이션하지 않는 경우 브리프에 실제 legacy
  경로와 보존 이유를 기록한다.
- User 프리셋은 파일명 기준 대소문자 무시 오름차순으로 정렬한다.
- 스캔형 User 뱅크는 에디터를 열 때와 저장이 끝난 직후 비재귀 방식으로 다시 스캔한다. 디스크
  하위 폴더를 프리셋 카테고리로 해석하지 않으며, 이는 UI의 `USER` 논리 폴더와 구분한다.
- 기존 파일 선택형 프리셋 API를 호환 목적으로 유지할 때도 별도 `Load` 버튼은 만들지 않고
  드롭다운 안의 `LOAD USER PRESET...` 명령으로 진입시킨다. 이는 스캔형 User 뱅크 완료로
  간주하지 않으며, 전환은 별도의 프리셋 마이그레이션으로 기록한다.
- 저장 후 방금 저장한 User 프리셋을 현재 항목으로 선택해 이름과 실제 상태가 어긋나지 않게 한다.
- 이전·다음, 저장 아이콘에는 기능과 길게 누르기 동작을 설명하는 짧은 툴팁을 제공한다.
- 저장 성공은 조작을 막지 않는 상태 메시지로 알리고, 폴더 생성 실패·저장 실패·손상된 파일은 사용자가 닫기 전까지 유지되는 경고로 알린다.

### 9.3 애널라이저 피드백 UX

`5.2`와 `7장`의 필요성 및 시각 기준을 통과한 애널라이저, 파라미터 예측 화면과 상태 기반
시각화에 다음 동작 규칙을 적용한다.

- 실제 입력이 있을 때만 입력 스펙트럼을 표시한다.
- 실제 시간 변화 데이터에는 사람이 변화를 읽을 수 있도록 시각적 스무딩을 적용한다.
- 파라미터 예측 화면은 노브, 호스트 템포와 상태 복원 변경을 오디오 분석 지연 없이 다시 계산한다.
- 표시용 어택, 릴리즈, 감쇠, 피크 홀드와 잔상 유지 시간을 브리프에 기록한다.
- 오디오, DSP, 파라미터, 호스트 상태 또는 사용자 입력 중 어느 것에도 연결되지 않은 자율 반복 움직임은 사용하지 않는다.
- 추상적 물성 변화는 원천 상태와 시각 매핑을 기록한 경우에만 허용하며 축, 단위와 교정 눈금을
  사용하지 않는다. 파라미터 예측은 DSP와 동일한 식으로 검증되는 축과 단위만 예외로 사용한다.
- 표시되는 응답과 실제 파라미터 의미를 일치시킨다.
- 양극성 모듈레이션은 실제 중앙값을 기준으로 양쪽 이동 폭을 동일하게 표현한다.
- 속도 파라미터는 이동 시간을 바꾸며 이동 범위를 바꾸지 않는다.
- 100%로 표시되는 값은 다른 무관한 컨트롤과 독립적으로 약속된 전체 범위를 의미해야 한다.
- 측정·상태 기반 화면은 무신호, 바이패스와 호스트 정지 시의 중립 상태를 정의한다. 파라미터
  예측 화면은 무신호에도 설정 결과를 유지할 수 있지만 입력이 계속 재생되는 듯한 움직임은 만들지 않는다.

### 9.4 오디오 플러그인에 적용할 상호작용 패턴

참고 기준: [SINS UI/UX Sample](https://capstoneid.github.io/sins-uiux-sample/)

오디오 플러그인의 짧고 반복적인 조작 흐름에 맞는 다음 패턴을 선별해 적용한다.

- `Carousel`: 프리셋처럼 같은 종류의 순차 항목에만 이전·현재·다음 구조를 사용한다. 현재 항목은 항상 읽을 수 있어야 하며 자동 전환하지 않는다.
- `Dropdown`: Factory와 User 프리셋처럼 항목 수가 변할 수 있는 선택 목록에 사용한다. 현재 선택과 그룹 구분을 명확히 표시하며, 둘 이상의 그룹은 `그룹 > 항목` 하위 메뉴로 접어 평면 목록의 과도한 길이를 피한다.
- `Icon Button + Tooltip`: 익숙한 아이콘은 공간을 절약하는 버튼으로 사용하되, 마우스 호버와 키보드 포커스 양쪽에서 짧은 설명을 제공한다. 필수 정보는 툴팁에만 숨기지 않는다.
- `Toast`: 저장 성공처럼 추가 판단이 필요 없는 완료 피드백은 조작을 막지 않는 토스트로 약 `3.2초` 표시한다.
- `Hover / Pressed / Disabled / Focus Ring`: 버튼과 셀렉터는 호버, 누름, 비활성, 키보드 포커스 상태를 서로 구별되게 표시한다. 포커스 링은 호버 외곽선과 시각적으로 달라야 한다.
- 아이콘 버튼과 프리셋 셀렉터는 host가 키 반환을 보장하는 경우 키보드 포커스와 `Enter` 실행을 지원한다. `Space` 전달을 보장할 수 없는 오디오 플러그인 control은 mouse click으로 키보드 포커스를 가져오지 않게 해 DAW transport를 우선하며, 어떤 경우에도 `Space`로 프리셋 팝업을 열지 않는다.
- 저장 실패, 폴더 생성 실패, 손상된 프리셋처럼 사용자의 조치가 필요한 오류는 사라지는 토스트만 사용하지 않고 닫기 전까지 유지되는 경고창으로 알린다.

다음 패턴은 오디오 플러그인의 집중도와 호스트 운용 흐름을 해치므로 기본 적용에서 제외한다.

- 프리셋 자동 재생, 무한 애니메이션 캐러셀, 콘텐츠를 임의로 넘기는 시간 기반 전환
- 단순 저장과 프리셋 선택에 모달·드로어·전체 화면 내비게이션을 추가하는 구조
- 로컬 프리셋처럼 즉시 읽을 수 있는 항목에 스켈레톤 로딩이나 긴 온보딩을 표시하는 구조
- 중요한 오류나 복구 방법을 짧게 사라지는 토스트에만 의존하는 구조

## 10. 브랜딩과 디자이너 제작 이미지 에셋

### 10.1 브랜드 공통 에셋

- 승인된 Team Impulse Impact 공통 시그니처의 투명 누끼본은 `5.1 헤더`의
  우측 브랜드 영역에 사용한다. 좌측 제품명, 중앙 프리셋과 같은 한 줄짜리 top bar에 두며
  프리셋 브라우저 안에 다시 배치하지 않는다.

### 10.1.1 명시 승인 제품별 마크 효과 은유 예외 등록부

현재 헤더 기본 정본은 `10.1`의 공통 시그니처다. 아래 등록부는 사용자가 해당 제품의 변형을
명시적으로 승인하고 제품 브리프가 정확한 행을 지정했을 때만 적용하는 예외다. 신규 플러그인과
일반 헤더 수정 작업에서 등록부를 이유로 자동 변형하거나 새 effect-fish 캡처를 만들지 않는다.

다음 등록부는 위 두 승인 조건을 충족했을 때만 적용하는 제품별 **예외 정본**이다. 등록부에 없는 임의 오브젝트를 완성된 기본 마크와 나란히
배치하는 방식은 허용하지 않는다. 다만 사용자가 명시한 마이크, 사람 팔, 계단, 반짝임처럼
장면 전체가 제품 원리를 설명하는 통제 요소는 표의 위치와 역할대로 허용한다. 의미를 접힌
꼬리 하나에 몰아주지 않고 몸체·얼굴·전체 실루엣·기준면·배경으로 분산한다. 100% UI 배율에서
기본 마크 계보가 먼저 보이고 제품 효과가 두 번째로 읽혀야 한다.

승인 마크는 좌표와 선 목록을 고정하는 원본이 아니라 같은 피시 계열로 읽히는 **이미지적
뉘앙스와 시각 DNA의 기준**이다. 제품 원리를 더 분명히 설명한다면 기존 선을 가리거나
덮어쓰고, 일부 경로 또는 전체 실루엣을 새로 그릴 수 있다. 통합 요소가 겹치면 실제
painter-order를 적용해 후면 요소를 전면 몸통·꼬리·액세서리의 불투명 면 뒤로 숨긴다.

레이어를 인위적으로 벌리지 않는다.

### 10.1.2 GitHub·TB Hub 불투명 카드 자산

GitHub와 TB Hub의 현재 제품 카드는 `1e DISPLAY` 계열을 사용한다. 이 제품별 카드 자산과
`10.1`의 플러그인 헤더용 공통 시그니처는 용도와 정본이 다른 두 계열이며 서로 덮어쓰지 않는다.

| 용도 | 규격 | 정본 경로 |
| --- | ---: | --- |
| 편집 가능한 DISPLAY 원본 | SVG `64 × 64 viewBox` | `logos/export/svg/TB_*.svg` |
| 로컬 256px 파생본 | `256 × 256` | `logos/export/png/TB_*_256.png` |
| 원격 vector mirror | SVG | `TB_Audio-Plugins/assets/brand/source/display-icons` |
| GitHub·TB Hub 카드 | `256 × 256` | `TB_Audio-Plugins/Hub/Logos` |
| 오프라인 fallback | `256 × 256` | `TB_Audio-Plugins/assets/plugins` |

- 원격 `display-icons` SVG와 로컬 `logos/export/svg` 대응 파일은 Git blob 기준으로 같아야 한다.
- `Hub/Logos`, `assets/plugins`와 로컬 256px 파생본의 대응 파일은 byte-identical해야 한다.
- 카드용 검정 정사각형 네 모서리는 불투명 배경을 유지한다.
- 카드용 DISPLAY 자산을 플러그인 헤더에 넣거나, 헤더용 투명 공통 시그니처를 Hub 카드에 자동 복사하지 않는다.
- GitHub·Hub 계열 변경은 별도 승인·검증·배포 작업이며 플러그인 헤더 동기화에 포함하지 않는다.

### 10.1.3 플러그인 헤더용 공통 시그니처 동기화

- 어두운 헤더는 `10.1`의 `signature-dark.png`를 정본으로 사용한다. 각 플러그인의
  `Source/Assets/tb_effect_logo.png`는 기존 BinaryData 호환 파일명으로 유지할 수 있지만 내용은

  `signature-light.png`를 사용한다.

  control bounds의 우측과 표시 로고 `Bp`의 좌측 사이, 표시 로고 `Bp`의 우측과 나사 외곽
  사이가 각각 최소 `4 px`인지 실제 editor 좌표로 별도 검증한다. 이 조건 때문에 로고 외곽을

- `.jucer`에 `tb_effect_logo.png`를 BinaryData resource로 등록하고, 생성된
  `BinaryData::tb_effect_logo_png`를 Editor 생성 시 한 번만 로드한다.
- 우상단에서는 투명 완성 이미지를 모든 제품에 동일한 **`48 × 48 px` 정사각형 슬롯**과
  `RectanglePlacement::centred`로 한 번만 그린다. draw 직전에 scoped
  `highResamplingQuality`를 적용한다. 종횡비 변경, tint, opacity 저하와 별도 배경 타일을
  금지한다.
- 위 우측 `48 × 48 px`·무배경 기본값의 명시 예외는 `5.5.2`와 `10.1.1`에 등록된

### 10.2 디자이너 제작 이미지 에셋

단순한 색상과 기본 도형만으로 제품의 재질, 깊이, 상태 차이와 시간 변화를 충분히 전달할 수
없다면 이미지 에셋을 정식 디자인 산출물로 제작한다.

| 에셋 분류 | 대표 대상 | 제작 목적 |
| --- | --- | --- |
| `material-base` | 섀시 결, 도장 입자, 고무, 유리 반사 | 제품 고유의 표면과 사람이 다듬은 제작감 |
| `depth-layer` | 접촉 그림자, 림, 베젤, 홈, 측면 두께 | 돌출·매입·눌림의 물리 관계 |
| `control-part` | 노브 캡, 슬라이더 핸들, 토글 레버, 눈금판 | 실제 아웃보드를 만지는 조작 감각 |
| `state-variant` | 기본, 호버, 눌림, 활성, 비활성 | 색상 외 형태·빛·깊이 변화로 상태 구분 |
| `dynamic-layer` | 바늘, 마커, 점등 세그먼트, 흔적 마스크 | 실제 값과 시간 변화의 가시화 |
| `visualization-overlay` | 입력·출력·감쇄·목표 영역의 선, 패턴, 범례 | 데이터 역할을 색상 외 방식으로 구분 |

에셋 제작 및 승인 규칙:

- 각 제품 고유 에셋에는 편집 가능한 마스터, 최종 출력본, 용도, 기준 배율, 알파 여부와 적용 상태를 기록한다.
- 외부 이미지나 텍스처를 사용하면 출처와 사용권, 디자이너의 수정 범위를 기록한다. 보정하지 않은 범용 텍스처를 핵심 제품 에셋으로 사용하지 않는다.
- 동적으로 변하는 포인터, 값, 미터, 활성광과 텍스트를 정적 배경에 합성하지 않는다.
- 같은 표면군은 광원 방향, 하이라이트 폭, 그림자 농도, 관찰 시점과 텍스처 스케일을 공유한다.
- 반복 텍스처는 전체 화면에서 타일 경계와 눈에 띄는 반복 무늬가 없어야 한다.
- 투명 에셋은 밝고 어두운 배경에서 검사해 흰 테두리, 검은 매트와 색 번짐이 없어야 한다.
- 같은 부품의 상태 변형은 중심점, 외곽 크기, 그림자 위치와 재질이 흔들리지 않아야 한다.
- 장식 에셋을 제거해도 라벨, 값, 활성 상태와 조작 가능 여부를 이해할 수 있어야 한다.
- 실제 플러그인 크기와 지원 배율에서 흐림, 계단 현상, 텍스처 뭉침, 경계선 두께 변화와 가독성을 검수한다.
- 디자이너 제작감은 특정 도구 사용 여부가 아니라 편집 가능한 원본, 의도 기록, 수동 아트 디렉션과 최종 시각 검수로 판단한다.

## 11. JUCE 구현 구조

- `PluginEditor.cpp`: 전체 구성, 레이아웃, 애널라이저, 표면 렌더링
- Custom `LookAndFeel`: 노브, 셀렉터, 버튼, 재질 표현
- 중앙 팔레트 상수: 모든 드로잉 코드가 공유하는 시맨틱 컬러
- `BinaryData`: 프로젝트 내부에 저장한 아이콘과 래스터 에셋을 임베드하며 로컬 절대 경로에 의존하지 않는다.
- Processor/Analyzer bridge: 실제 DSP를 정직하게 표시하는 데 필요한 값만 전달

그림을 쉽게 만들기 위해 DSP 동작을 바꾸지 않는다. 시각화가 실제 DSP 응답을 보여준다고 주장한다면
오디오 동작과 화면을 함께 검증한다.

### 13.4 제품별 QA: TB_Delay 위계

- [ ] 100% 배율 `960 × 650 px`에서 좌측 `TB_DELAY`는 21 px 이상의 굵은 고딕 텍스트,
      중앙 preset은 Supporting, 우측 물고기 로고는 등록된 Delay 예외인 3단 잔상으로 표시한다.
      본문은 `제품명 → Delay Map → DELAY TIME·FEEDBACK → preset` 순서로 읽힌다.
- [ ] 독립 헤더 양 끝에 작은 랙 나사가 있고, 프리셋 드롭다운은 에디터 중심에 고정되며
      `[이전] [프리셋] [다음] [저장]` 순서를 유지한다.
- [ ] Delay Map은 `900 × 200 px` 이상이고 그려진 외곽 베젤 폭이 2×2 control board의
      그려진 외곽 폭과 같다. 네 음악적 섹션은 같은 광원의 얕은 양각 peer panel이고 Map은 매입형이다.
- [ ] 기본 Sync 화면의 rotary body는 13개, 수평 슬라이더는 `MIX`·`OUTPUT` 2개다.
      `OFFSET`, `SPACING`, `SWING`, filter/color/modulation/diffusion 상세값, `DIVERGE`,
      `GRAIN SIZE`, `DENSITY`, `SPRAY`, `TIME CHANGE`는 component와 hit target이 없다.
- [ ] 네 사분면은 `REPEAT` 4개, `STEREO` 2개, `CHARACTER / SPACE` 3개,
      `TRANSFORM` 4개 rotary body로 읽힌다. `SHIFT ROUTE`와 `FREEZE`는 독립 결과로 남는다.
- [ ] 결과 중심 라벨은 내부 구현명보다 먼저 읽혀야 한다. TB_Delay에서는 `TAPS`를
      `ECHOES`, `TYPE`을 `CHARACTER`, `COLOR` macro를 `TONE`, `SPACE` macro를
      `DIFFUSION`, `GRAIN MIX`를 `GRAIN`, `BUILD / ONCE`를 `SHIFT ROUTE`로 표시할 수
      있으며 host parameter ID·state ID는 유지한다. stepped choice의 값도 `1 echo`처럼
      단위를 포함해 현재 결과를 바로 읽을 수 있어야 한다.
- [ ] `TONE`과 `DIFFUSION`은 `CLEAN/TIGHT – BASE – WORN/WASH` 방향을 값 영역에 표시한다.
      BASE에서 기존 preset의 소리가 같고 매크로 조작이 숨은 상세 APVTS 값을 변경하지 않는다.
- [ ] Standard `41 px` 노브의 값 arc가 시작점부터 현재값까지 채워지고, 하단 MIX는 최소점,
      OUTPUT은 0 dB에서 현재값까지 굵은 amount track을 채우며 서로 같은 높이·폭이다.
- [ ] `TIME MODE`는 `FREE / SYNC / TUNE` dropdown이다. 한 `DELAY TIME` 위치에서 Free는
      ms, Sync는 음표 분할, Tune은 튜닝 주파수를 표시·조절하며 기존 Tune preset의 상태와
      소리를 보존한다. 바로 아래 같은 폭의 UI-only momentary `TAP`을 두고 첫 탭은 상태를
      바꾸지 않는다. 두 번째부터 Free/Tune은 측정 interval을 `time`, Sync는 host BPM의
      최근접 기존 `division`에 적용하되 현재 모드를 유지한다. TAP은 키보드 포커스와 DAW의
      `Space` transport를 소비하지 않는다. 기존 `TIME CHANGE` 값은 preset/host 호환용으로만 유지한다.
- [ ] 입력 기준선에서 위 L·아래 R lane으로 이어지는 첫 L/R anchor가 후속 echo,
      decay triangle, grain support와 grid보다 먼저 보이며 x축 `10 ms–5 s`, `>5 s`
      overflow와 실제 DSP 계산이 일치한다. 10 ms의 첫 event도 최소 5.5 px marker로
      남겨 원점에 묻히지 않아야 한다.
- [ ] Aged Brass 섹션 표식은 짧은 선과 작은 면적으로 제한되고 활성 포인터·값 arc·L anchor와
      같은 상태 강도로 오인되지 않으며, Smoked Sage는 R/return 정보에 제한된다.
- [ ] Factory bank는 문서 순서의 12개 논리 폴더 × 10개, 총 120개이고 루트에는 이 폴더와
      `USER`만 표시된다. 기존 0–99 program의 호스트 recall을 보존한 채 100–119를
      append하며, 120개 전체가 범위·고유성·Freeze Off·finite/bounded render 검사를 통과한다.
